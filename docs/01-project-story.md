# Project Story — FreightFlow 360

## Overview

FreightFlow 360 is a full-stack logistics-inspired web application built with Angular, Spring Boot, REST APIs, and a SQL database. It combines a public freight/logistics website style with a working admin portal for products, inventory, low-stock tracking, orders, and dashboard metrics.

This project has a real development story behind it. It did not start as a random template or a simple static website. It started as a warehouse management project, was rebuilt after the original source files were lost, and later evolved into FreightFlow 360 after a real logistics company tour helped shape the branding direction.

---

## Original Project Idea

The original idea was a Warehouse Order and Inventory Management Portal.

The main user was a warehouse admin who needed a simple way to:

- Manage products
- Track inventory levels
- View low-stock items
- Create customer orders
- View order details
- Update order status
- See warehouse activity from a dashboard

The goal was not to build a huge enterprise warehouse system. The goal was to build a realistic full-stack application that showed backend development, frontend development, database modeling, REST API design, validation, and full-stack integration.

---

## Rebuilding the Warehouse Project

At one point, the original source files were lost. Instead of stopping the project, the warehouse system was rebuilt from scratch into a stable working version.

That rebuild helped define the main technical foundation of the application:

- Spring Boot backend
- Angular frontend
- SQL database
- Product management
- Inventory management
- Order management
- Dashboard summary data
- Frontend/backend API integration

The rebuilt warehouse portal became the safe, working version of the project. It proved that the core workflows worked before any extra design or branding customization was added.

---

## Branding Inspiration from the ArcBest Tour

The branding direction for FreightFlow 360 came from a college-organized day tour at **ArcBest**.

During the tour, I got to see how a real logistics company presents its services, operations, technology, transportation network, and customer-facing platform experience. That visit changed how I looked at my project. Before the tour, the project felt like a normal warehouse admin portal. It worked, but it did not feel like a complete company-style application.

After seeing a real freight and logistics environment, I realized I could take the same working warehouse foundation and give it a stronger identity. Instead of keeping it as a plain inventory project, I could turn it into a logistics-inspired platform with public website pages, shipper/carrier sections, tracking-style actions, and a more professional transportation brand.

FreightFlow 360 is not affiliated with ArcBest, and the goal was not to copy ArcBest. The tour simply gave me the idea and motivation to convert a basic warehouse project into a more polished full-stack logistics platform.

---

## Why FreightFlow 360 Was Created

After the rebuilt warehouse project was working, a new private repository was created called **FreightFlow 360**.

The reason for creating a new repo was simple: the rebuilt warehouse version was stable, so it made sense to keep it safe as a backup and experiment in a separate place.

FreightFlow 360 became the version where the project could be customized more freely:

- New logistics/freight-style branding
- Public-facing website pages
- Cleaner navigation
- Shipper/carrier style sections
- Tracking-style actions
- A more professional transportation platform feel
- A working admin portal behind the public website

This approach made the development safer. The original warehouse project stayed protected, while FreightFlow 360 became the improved and customized version.

---

## How the Project Evolved

The project evolved in three main stages.

### Stage 1: Warehouse Portal Idea

The first version focused on a simple warehouse admin workflow:

- Products
- Inventory
- Low-stock alerts
- Orders
- Dashboard summaries

This stage was mostly about defining the project scope and deciding what a warehouse admin should be able to do.

### Stage 2: Rebuilt Full-Stack Version

After the original files were lost, the project was rebuilt into a stable working full-stack application.

This stage focused on making the app actually work:

- Angular pages connected to Spring Boot APIs
- Product CRUD operations
- Low-stock filtering
- Order creation
- Inventory reduction
- Order status updates
- Dashboard data from the backend

### Stage 3: FreightFlow 360 Branding and Customization

After the ArcBest tour and after the rebuilt app was stable, the project was copied into a new repo and redesigned as FreightFlow 360.

This stage added the logistics company-style presentation:

- Public homepage
- Shippers page
- Carriers page
- Technology page
- Tracking-style navigation
- Company/about pages
- More polished visual direction
- Admin portal kept as the working internal system

This made the project feel less like a class CRUD assignment and more like a real logistics platform prototype.

## Deployment Story

FreightFlow 360 was also deployed online to make it feel closer to a real project.

The deployment setup used:

- **Aiven** for managed SQL database hosting
- **Render** for application hosting/deployment
- **Cloudflare** for domain and DNS setup

This deployment process helped test the project outside local development and exposed real-world issues such as environment variables, database connection strings, CORS settings, frontend API URLs, and hosted backend/frontend communication.
